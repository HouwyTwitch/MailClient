# Корпоративная почта — клиент Microsoft Exchange и IMAP для Windows

Почтовый клиент для Windows 10/11. Поддерживает два типа серверов:

- **Microsoft Exchange Server** по протоколу **EWS (Exchange Web Services)**. Работают почта, контакты, адресная книга
  организации, приглашения на встречи и автоответы. Поддерживаются собственные (on-premises) серверы Exchange
  от 2010 SP2 до 2019 / Subscription Edition.
- **IMAP + SMTP**: Яндекс 360, Mail.ru / VK WorkSpace, Rambler, Exchange с включённым IMAP,
  Dovecot, CommuniGate и другие стандартные серверы. Работает только почта.

Программа рассчитана на российские организации. Интерфейс полностью на русском языке.

## Возможности

**Почта**
- Входящие, отправленные, черновики, удалённые и все пользовательские папки (дерево папок).
- Создание, переименование, перемещение, удаление и очистка папок.
- Счётчик непрочитанных у папки включает её подпапки (подсказка показывает, сколько в самой папке
  и сколько в подпапках).
- Чтение HTML- и текстовых писем, встроенные изображения (`cid:`), печать.
- Ответ, ответ всем, пересылка: цитата исходного письма, его вложения (при пересылке) и связь
  с цепочкой переписки (заголовки In-Reply-To/References).
- Редактор письма: шрифт и размер, полужирный, курсив, подчёркнутый и зачёркнутый текст, цвет
  текста и выделение маркером, выравнивание, списки и отступы, ссылки, изображения в тексте
  (из файла или скриншот из буфера обмена), горизонтальная линия, отмена/повтор. Шрифт новых
  писем задаётся в параметрах и сохраняется в письме — получатель видит его так же.
- Подпись с оформлением (шрифт, цвет, ссылки, логотип) для каждой учётной записи: отдельно для новых
  писем и для ответов (в ответе подпись стоит над исходным письмом). Её можно заполнить из адресной
  книги (ФИО, должность, отдел, телефоны) или взять из Outlook в Интернете. При смене отправителя
  в окне письма подпись меняется на подпись выбранного ящика.
- Флажок важности, запрос уведомления о прочтении.
- Подсказки адресатов из адресной книги организации (Active Directory) и проверка имён:
  можно написать «Иванов», и адрес будет найден.
- Вложения: добавление кнопкой или перетаскиванием, предупреждение о превышении лимита размера.
  Можно открыть, сохранить или сохранить все. К сохранённым файлам добавляется
  метка «загружено из интернета» (Mark of the Web), поэтому Office открывает их в режиме
  защищённого просмотра. Перед открытием исполняемых файлов программа предупреждает.
- Черновики: сохранение и продолжение работы; при закрытии окна программа предлагает сохранить письмо.
- Отметки «прочитано/не прочитано», флажки, перемещение и копирование (в том числе
  перетаскиванием на папку), нежелательная почта, удаление (`Delete`) и безвозвратное удаление (`Shift+Delete`).
- Выбор нескольких писем (`Ctrl`/`Shift`+щелчок, `Ctrl+A`): их можно разом перетащить на папку
  (с `Ctrl` — скопировать), переместить, отметить прочитанными или удалить.
- В заголовке письма отправитель и получатели показаны по именам. Щелчок по имени открывает карточку
  с адресом, а для Exchange — с должностью, отделом и телефонами из адресной книги организации;
  из карточки можно написать письмо, скопировать адрес или добавить человека в контакты.
  Длинный список рассылки занимает не больше 15% высоты области просмотра и прокручивается.
- Поиск по папке на сервере (AQS). Без связи поиск идёт по локальной копии.
- Экспорт писем в `.eml` и импорт `.eml` (в том числе перетаскиванием файлов из Проводника на папку).
- Общие почтовые ящики (при наличии прав полного доступа и «Отправить как»).

**Контакты, приглашения, автоответы, правила пересылки**
- Приглашения на встречи в письмах: время и место показываются в письме, ответ
  (принять / под вопросом / отклонить) отправляется организатору.
- Личные контакты: просмотр, создание, изменение, удаление. Поиск в адресной книге организации.
- Автоответы («Нет на месте»): включение, расписание, отдельные тексты для своих и внешних отправителей.
- Правила пересылки и переадресации, которые выполняет сервер: условия (отправитель, слова в теме
  или тексте), способ (переадресовать, переслать, переслать вложением), копия в ящике, порядок правил.
  Правила, созданные в Outlook, сохраняются как есть — их можно включить, выключить, переименовать или удалить.

**Работа в организации**
- Автоматический поиск сервера по адресу почты (Autodiscover).
- Вход по логину и паролю (NTLM/Kerberos, форматы `ДОМЕН\пользователь` и `user@domain`)
  или единый вход Windows (SSO) на компьютерах в домене.
- Доверие к **корневому сертификату организации или «Russian Trusted Root CA» (Минцифры)**
  без установки его в хранилище Windows. Сертификат применяется только к серверу этой учётной записи.
- Предварительная настройка администратором через групповые политики или файл `organization.json`:
  сотруднику остаётся ввести только логин и пароль.
- Несколько учётных записей одновременно.
- Автономный режим: письма хранятся в локальной копии (SQLite), синхронизация идёт
  инкрементально (`SyncFolderItems`). После восстановления связи программа сама продолжает работу.
- Значок в области уведомлений, уведомления о новых письмах, автозапуск, регистрация обработчика ссылок `mailto:`.
- Светлая и тёмная темы.

## Подключение по IMAP (Яндекс 360, Mail.ru и др.)

1. В окне учётной записи выберите тип сервера **«IMAP / SMTP»** и введите адрес почты.
   Для Яндекса, Mail.ru и Rambler серверы подставятся автоматически. Для других доменов
   нажмите **«Заполнить по адресу»** или выберите службу в списке.
2. Яндекс 360 и Mail.ru **не принимают обычный пароль** в сторонних программах. Создайте
   **пароль приложения** и введите его в поле «Пароль»:
   - Яндекс: Яндекс ID → Безопасность → Пароли приложений → «Почта» (IMAP);
   - Mail.ru: Настройки → Безопасность → Пароли для внешних приложений.
3. Включите доступ по IMAP в настройках почты (Яндекс: Настройки → Почтовые программы).

| Служба | IMAP | SMTP |
|---|---|---|
| Яндекс 360 | imap.yandex.ru : 993, SSL/TLS | smtp.yandex.ru : 465, SSL/TLS |
| Mail.ru | imap.mail.ru : 993, SSL/TLS | smtp.mail.ru : 465, SSL/TLS |
| Rambler | imap.rambler.ru : 993, SSL/TLS | smtp.rambler.ru : 465, SSL/TLS |
| Exchange по IMAP | mail.домен : 993, SSL/TLS | mail.домен : 587, STARTTLS |

По IMAP работает вся почта: папки, синхронизация, вложения, ответы с цитатой, черновики,
поиск, флажки и импорт/экспорт .eml. Контакты и автоответы в протоколе
IMAP отсутствуют, поэтому для таких учётных записей эти разделы скрыты. Правила переадресации
работают на серверах с ManageSieve (Dovecot и др., порт 4190): программа хранит их в отдельном блоке
активного Sieve-скрипта и не трогает остальные фильтры. Яндекс 360 и Mail.ru ManageSieve не
предоставляют — у них пересылка настраивается в веб-интерфейсе. Адреса в поле
«Кому» подсказываются по вашей переписке.

## Кодировки

Исходящие письма всегда отправляются в UTF-8 с явным указанием кодировки и в 7-битном
кодировании (quoted-printable/base64), поэтому русский текст не искажается ни в «Отправленных»,
ни у получателей со старыми почтовыми серверами. Во входящих письмах без указанной (или с
неверно указанной) кодировкой — и в тексте, и в заголовках (отправитель, тема) — кодировка
определяется автоматически по статистике русского текста: UTF-8,
windows-1251, KOI8-R, CP866 (DOS), ISO-8859-5, Mac. Для Exchange тема и отправитель в окне
письма берутся из данных сервера (как в списке писем); если MIME-копия письма с ними не
совпадает, текст письма тоже берётся у Exchange в уже раскодированном виде. Письма, которые уже были
сохранены в «Отправленных» предыдущей версией программы, могут остаться искажёнными.

## Вход в Exchange

- По умолчанию используется **NTLM**: программа отвечает только на запрос NTLM через пакет
  Windows SSPI «NTLM» и не пытается войти через Kerberos, который часто не настроен для
  балансировщиков и DNS-псевдонимов.
- **Пароль можно не вводить.** Тогда вход выполняется под текущей учётной записью Windows.
- Логин `ДОМЕН\пользователь` делится на домен и имя, а `пользователь@домен` передаётся как есть.
- Для локального Exchange дополнительные заголовки (`X-AnchorMailbox`) не передаются.
- Проверка подключения — один запрос `GetFolder msgfolderroot` со схемой Exchange2007_SP1,
  которую принимает любой Exchange. Версия сервера определяется по его ответу.
- Программа делает **одну попытку входа** — ровно с теми логином, доменом и способом
  аутентификации, которые указаны в настройках. Другие написания логина и другие способы она сама
  не перебирает: многократные неудачные попытки блокируют учётную запись в домене. Если сервер
  отклонил вход, фоновая синхронизация останавливается и не повторяет вход по таймеру; следующая
  попытка — только после ввода нового пароля или нажатия «Обновить». Автообнаружение тоже
  прекращается, как только сервер отклонил учётные данные. Для IMAP/SMTP используется один способ
  входа (AUTH PLAIN, иначе AUTH LOGIN, иначе команда LOGIN).

Для других серверов в поле «Аутентификация» есть варианты «Обычный пароль (Basic)», Kerberos
и «Автоматически».

## Синхронизация и операции

- **Папки:** стандартные папки запрашиваются по именам (только идентификаторы), затем выполняется
  `SyncFolderHierarchy` от корня с сохранённым состоянием, так что повторно передаются только
  изменения. Сведения о папках (`GetFolder`) запрашиваются пачками по 10.
- **Письма:** `SyncFolderItems` возвращает только идентификаторы (до 256 изменений за запрос).
  Заголовки писем запрашиваются `GetItem` пачками по 10, как рекомендует Microsoft. Изменения
  применяются в том порядке, в каком их прислал сервер; уведомление «новое письмо» показывается
  только для действительно новых писем.
- При перегрузке сервера (`ErrorServerBusy`, `ErrorExceededConnectionCount`) все запросы учётной
  записи делают общую паузу той длительности, которую назвал сервер (или 5 секунд).
- Одновременно выполняется не больше 4 запросов. Если соединение оборвалось, повторяются запросы на
  чтение и изменения, которые можно безопасно выполнить дважды (прочитано, флажок, удаление,
  перемещение). Отправка писем и создание черновиков не повторяются, чтобы письмо не ушло дважды.
  Зато после паузы дольше 10 секунд перед ними идёт короткая проверка соединения (`GetFolder`).
  Сетевые экраны часто молча закрывают простаивающие соединения, и без проверки первый запрос
  после паузы получал бы «Удалённый хост принудительно разорвал существующее подключение».
  Соединения поддерживаются пакетами TCP keep-alive и закрываются после 50 секунд простоя.
- Отметка «прочитано», сделанная без связи, сохраняется на компьютере и уходит на сервер при
  следующей синхронизации. Синхронизация её не отменяет.
- Каждая папка синхронизируется независимо: длинная первая синхронизация «Входящих» не мешает
  открывать другие папки. Ход синхронизации показывается в строке состояния.

| Действие | Как выполняется |
|---|---|
| Открыть письмо | `GetItem` с `IncludeMimeContent`; письмо разбирается на компьютере, вложения берутся из того же MIME без лишних запросов |
| Отправить | Письмо собирается как MIME (цитата, `In-Reply-To`/`References`, вложения пересылаемого письма), `CreateItem SendOnly`; получатели скрытой копии передаются отдельно и в отправленном письме не видны; копия кладётся в «Отправленные» |
| Черновик, импорт .eml | `CreateItem SaveOnly` с MIME и флагами MAPI: черновик — READ\|UNSENT, импорт — READ\|UNMODIFIED |
| Прочитано / не прочитано | `UpdateItem` без ChangeKey, `ConflictResolution=AlwaysOverwrite` |
| Флажок | `item:Flag` и `PR_FLAG_STATUS` одним изменением (виден и в Outlook, и на Exchange 2010) |
| Прочитать все | `MarkAllItemsAsRead` (Exchange 2013+), на старых серверах — по одному письму |
| Нежелательная почта / «Не спам» | `MarkAsJunk` (Exchange 2013+), на Exchange 2010 — перемещение |
| Удалить | перемещение в «Удалённые»; из «Удалённых» — `HardDelete` пачками по 1000 |
| Переместить / копировать | `MoveItem`/`CopyItem` с `ReturnNewItemIds` |
| Папки | создание `IPF.Note`, переименование, удаление в «Удалённые», очистка «Удалённых» — `HardDelete` |
| Контакты, адресная книга, приглашения, автоответы | стандартные операции EWS (`FindItem`, `ResolveNames`, `CreateItem`, `Get/SetUserOofSettings`) |
| Правила пересылки | `GetInboxRules` / `UpdateInboxRules` (Exchange 2010 SP1+): отправляются только изменения |

В меню ⚙ есть пункт «Сохранить отчёт для техподдержки». Он создаёт ZIP-архив с журналами,
настройками без паролей и сертификатов и сведениями о системе.

## Если программа пишет «неверное имя пользователя или пароль»

- **Exchange:** оставьте пароль пустым, если другие почтовые программы на этом компьютере
  подключаются без пароля, и нажмите «Проверить подключение». Попытка записывается в журнал
  (⚙ → «Открыть папку журналов») вместе со способами входа, которые предлагает сервер.
  Пароли в журнал не попадают.
- **Microsoft 365:** если сервер принимает только OAuth, вход по паролю невозможен.
  Подключитесь по IMAP с паролем приложения или обратитесь к администратору.
- **Яндекс / Mail.ru:** нужен пароль приложения, а не пароль от почты (см. выше).

## Сторонние компоненты

Программа написана самостоятельно; готовые библиотеки (MailKit, MimeKit, SQLite, WebView2 и др.)
подключаются пакетами NuGet. Их перечень и лицензии — в `THIRD-PARTY-NOTICES.txt` (устанавливается
рядом с программой, открывается кнопкой «Сторонние компоненты» в окне «О программе»).

## Безопасность и персональные данные

- Телеметрии нет. Программа обращается только к серверу Exchange организации.
- Пароли хранятся на компьютере пользователя, зашифрованные Windows DPAPI.
  Расшифровать их может только тот же пользователь Windows на том же компьютере.
- Письма показываются с отключённым JavaScript и строгой политикой CSP. Изображения из
  интернета (трекинговые пиксели) по умолчанию заблокированы; их можно разрешить для
  одного письма или для доверенного отправителя.
- Ссылки из писем открываются во внешнем браузере. Разрешены только схемы `http`, `https` и `mailto`.
- Незашифрованный HTTP разрешён только после явного предупреждения.
- Журнал работы ведётся для техподдержки (`%LOCALAPPDATA%\MailClient\logs`, хранится 14 дней)
  и не содержит паролей и текстов писем.

## Системные требования

- Windows 10 версии 1809 и новее или Windows 11, x64.
- Microsoft Edge WebView2 Runtime (в Windows 11 и обновлённой Windows 10 уже есть).
  Без него письма показываются в упрощённом текстовом виде.
- Microsoft Exchange Server 2010 SP2 и новее с включённым EWS
  (`https://<сервер>/EWS/Exchange.asmx`).
- Устанавливать .NET не нужно: программа поставляется самодостаточным файлом.

Перенос на Astra Linux: исследование, варианты и план — [`docs/astra-linux.md`](docs/astra-linux.md).
Версия для Linux (Astra Linux SE 1.7/1.8, Debian, Ubuntu): пакет `.deb` из CI, установка и настройка — [`docs/linux.md`](docs/linux.md).

## Установка и развёртывание

1. Соберите установщик (см. ниже) или возьмите `MailClient-Setup-*.exe` из артефактов CI.
2. Установка вручную: запустите установщик. Тихая установка для всех пользователей:
   `MailClient-Setup-1.0.0.exe /VERYSILENT /SUPPRESSMSGBOXES /ALLUSERS`.
3. Предварительная настройка (необязательно). Есть два способа:
   - групповые политики. Административные шаблоны лежат в [`deploy/admx`](deploy/admx): скопируйте
     `MailClient.admx` и папки `ru-RU`/`en-US` в центральное хранилище политик
     (`\\домен\SYSVOL\домен\Policies\PolicyDefinitions`) или в `C:\Windows\PolicyDefinitions`.
     Параметры появятся в разделе «Административные шаблоны → Корпоративная почта» как для компьютера,
     так и для пользователя (при совпадении приоритет у компьютера). Без шаблонов можно записать значения
     в ключ `HKLM\SOFTWARE\Policies\MailClient` напрямую, пример в
     [`deploy/MailClient-policy.example.reg`](deploy/MailClient-policy.example.reg);
   - файл `organization.json` рядом с `MailClient.exe`, пример в
     [`deploy/organization.example.json`](deploy/organization.example.json).
     Если положить его в `deploy\organization.json` перед сборкой, установщик включит его автоматически.

   | Параметр | Назначение |
   |---|---|
   | `EwsUrl` | Адрес EWS, например `https://mail.company.ru/EWS/Exchange.asmx` |
   | `Domain` | Домен Windows для входа |
   | `EmailDomain` | Почтовый домен: можно ввести `ivanov`, и адрес дополнится до `ivanov@company.ru` |
   | `AuthMethod` | `Password` или `IntegratedWindows` (единый вход) |
   | `ServerVersion` | `Exchange2016` (2016/2019/SE), `Exchange2013_SP1`, `Exchange2013`, `Exchange2010_SP2` |
   | `TrustedRootCertificateFile` | Путь к корневому сертификату внутреннего УЦ или Russian Trusted Root CA |
   | `LockServerSettings` | `1` — запретить пользователям менять адрес сервера |
   | `Protocol` | `Exchange` (по умолчанию) или `Imap` |
   | `ImapHost`, `ImapPort`, `SmtpHost`, `SmtpPort` | Серверы для учётных записей IMAP |
   | `DisableForwardingRules` | `1` — запретить настройку правил пересылки в программе. Запрет на сервере (удалённые домены, правила транспорта Exchange) действует и для других программ |

   Политики читаются при запуске программы.
4. Прокси: программа использует системные настройки прокси Windows (включая сценарии PAC/WPAD) и входит
   на прокси под учётной записью пользователя Windows. Если прокси всё равно отвечает «407», добавьте адрес
   почтового сервера в исключения прокси.

## Сборка

Нужен .NET 10 SDK (версия задана в `global.json`), для установщика — Inno Setup 6.
Версии всех зависимостей собраны в одном файле — `Directory.Packages.props`.

```powershell
# тесты + MailClient.exe + установщик (если установлен Inno Setup)
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1 -Version 1.0.0
```

Результат: `publish\win-x64\MailClient.exe` и `publish\MailClient-Setup-1.0.0.exe`.
При каждом push GitHub Actions собирает то же самое на Windows (`.github/workflows/build.yml`)
и прикладывает к сборке файл контрольных сумм `SHA256SUMS.txt`.

Выпуск версии: поставьте тег `vX.Y.Z` (например, `git tag v1.0.0 && git push origin v1.0.0`). CI соберёт
программу с этой версией (номер сборки CI добавляется в версию файла) и опубликует GitHub Release
с установщиком и контрольными суммами. Номер версии и коммит видны в окне «О программе» и в отчёте для техподдержки.

Подпись кода: добавьте в секреты репозитория `SIGNING_CERT_PFX` (сертификат подписи кода в формате PFX,
закодированный в base64) и `SIGNING_CERT_PASSWORD`. Тогда CI подпишет `MailClient.exe`, установщик и
деинсталлятор с меткой времени (сервер меток можно сменить переменной репозитория `SIGNING_TIMESTAMP_URL`).
Подписанная программа не вызывает предупреждений SmartScreen и проходит политики AppLocker/WDAC по издателю.

Тесты: `dotnet test --project tests/MailClient.Tests`. Дополнительные проверки включаются переменными окружения:
`MAILCLIENT_IMAP_TEST=1` — сквозные тесты с настоящим IMAP/SMTP-сервером (`tests/imap-test-env.md`),
`EDITOR_TEST=1` — редактор писем в Chromium (нужны Node.js и пакет `playwright`, `tests/editor/editor.check.js`).

## Архитектура

```
src/
  MailClient.Core       модели, интерфейс IMailProvider, локальный кэш (SQLite), синхронизация,
                        безопасный HTML-рендеринг
  MailClient.Exchange   клиент EWS (SOAP): папки, письма, вложения, контакты, приглашения,
                        автоответы, адресная книга; Autodiscover; NTLM/Kerberos/SSO; доверие к УЦ
  MailClient.Imap       IMAP + SMTP на основе MailKit: инкрементальная синхронизация (UID/CONDSTORE),
                        ответы с цитатой и заголовками In-Reply-To, имена вложений по RFC 2047
  MailClient.Linux      приложение для Linux (Avalonia, WebKitGTK): общие с WPF модели представления и сервисы,
                        свои реализации диалогов, хранения паролей, политик и интеграции с рабочим столом
  MailClient.App        приложение WPF (.NET 10, MVVM): интерфейс, WebView2, хранение секретов (DPAPI),
                        значок в трее, политики организации
tests/
  MailClient.Tests      более 100 тестов: каждый запрос к EWS проверяется по правилам протокола
                        (EwsRequestRules.txt — порядок элементов, обязательные части, допустимые
                        значения); IMAP/SMTP — сквозные тесты на реальном сервере Dovecot
                        (tests/imap-test-env.md); редактор писем — в Chromium (tests/editor)
```

Протокольный слой отделён интерфейсом `IMailProvider`: при необходимости можно добавить
другой серверный модуль (например, Microsoft Graph), не меняя интерфейс программы.

## Ограничения текущей версии

- Протокол EWS проверен автоматическими тестами по правилам протокола, но не на живом сервере
  Exchange. Для дополнительной проверки по схеме вашего сервера скачайте с него
  `https://<сервер>/EWS/messages.xsd` и `types.xsd` в одну папку и запустите тесты с переменной
  `EWS_SCHEMA_DIR=<папка>`. Протокол IMAP/SMTP проверен на реальном сервере Dovecot. **Перед массовым внедрением
  нужен пилот на реальном сервере организации** (рекомендуется 5–10 пользователей).
- TLS по ГОСТ (КриптоПро CSP) не поддерживается: сервер Exchange должен использовать
  обычный сертификат RSA/ECDSA. Именно так настроено большинство установок Exchange.
- Электронная подпись и шифрование писем (S/MIME, ГОСТ) не поддерживаются.
  Файлы подписи `.sig`/`.p7s` передаются как обычные вложения.
- Microsoft 365 / Exchange Online не поддерживается: в этой сборке нет входа через OAuth,
  а Microsoft отключает EWS в Exchange Online.
- Календарь и задачи не входят в программу (приглашения на встречи в письмах поддерживаются).
  Общедоступные папки (Public Folders) не поддерживаются.
