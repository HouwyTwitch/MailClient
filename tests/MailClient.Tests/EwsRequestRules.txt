# Structure of the EWS requests this client sends (operations, SOAP headers and everything inside them).
# The tests check every request against these rules, so a wrong element order, a missing required part
# or a misspelled value is caught before a real Exchange server rejects it with ErrorSchemaValidation.
#
#   Name = A! B (C | D)* E   children in protocol order; ! required, * repeatable, (C | D) alternatives in one place
#   Name : text              leaf element and its content: text, boolean, integer, datetime, base64, proptag,
#   Name : v1 | v2              or the allowed values
#   Name =                   empty element (attributes only)
#     @Attr! : …             attribute (! required) and its content, same notation
#   Parent/Name              rule for Name inside Parent only (that name has another structure elsewhere)
#
# Only what the client uses is listed: anything else is reported, so a request that gains a new element,
# attribute or value needs a matching line here (in the position the EWS protocol defines for it).
