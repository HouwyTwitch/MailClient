# Перенос на Astra Linux: исследование

Состояние на октябрь 2026 года. Цифры по коду взяты из этого репозитория. Утверждения о сторонних
продуктах сделаны по открытым источникам (список в конце). Пункты с пометкой **проверить на стенде**
нужно подтвердить на настоящей Astra Linux до начала работ.

## Вывод

Перенос реален и не требует переписывать почтовую часть. Нужен новый интерфейс на **Avalonia 12**.
Встроенный браузер Avalonia (WebKitGTK на Linux) с версии 12 стал открытым (MIT) и заменяет WebView2.
Из того же кода можно собирать и Windows-версию, тогда одна программа обслуживает обе ОС.
Ориентировочно это **2–2,5 месяца работы одного разработчика**, включая стенд, упаковку в .deb и подпись
для замкнутой программной среды (ЗПС).

Запускать текущую WPF-версию под Wine не стоит. WPF и WebView2 там работают плохо, а для аттестованных
систем такой вариант не подходит.

## Что уже работает на Linux

| Проект | Объём | Платформа |
|---|---|---|
| `MailClient.Core`: модели, кэш SQLite, синхронизация, MIME, кодировки, Sieve | ≈2,2 тыс. строк | `net10.0`, кроссплатформенный |
| `MailClient.Exchange`: EWS, Autodiscover, правила, NTLM/Kerberos | ≈2,3 тыс. строк | `net10.0`, кроссплатформенный |
| `MailClient.Imap`: IMAP/SMTP (MailKit), ManageSieve | ≈1,2 тыс. строк | `net10.0`, кроссплатформенный |
| `MailClient.App`: интерфейс WPF | ≈6 тыс. строк C# + 2,2 тыс. строк XAML | только Windows |

Все 136 автотестов (протоколы, кэш, кодировки, живые IMAP/SMTP/ManageSieve на Dovecot) уже выполняются
на Linux (Ubuntu) в среде разработки. Почтовая логика переносится без изменений.

## Что привязано к Windows и чем заменить

| Сейчас (Windows) | Замена на Linux |
|---|---|
| WPF (окна, стили, XAML) | Avalonia 12. Синтаксис XAML близок к WPF, модели представления на CommunityToolkit.Mvvm переносятся почти как есть. Разметку и стили придётся переписать |
| WebView2: просмотр писем, редактор `editor.html`, печать | `Avalonia.Controls.WebView` (NativeWebView), на Linux это WebKitGTK. Страница редактора уже общается с программой через `postMessage` и переносится без изменений. Печать идёт через диалог печати WebKitGTK |
| DPAPI (хранение паролей) | Secret Service (libsecret) при наличии хранилища ключей в сессии; иначе файл, доступный только владельцу. **Проверить на стенде**, какое хранилище есть в Fly |
| Групповые политики (`HKLM\SOFTWARE\Policies\MailClient`) | Файл `/etc/mailclient/policy.json` с теми же параметрами. Раскладывается средствами ALD Pro, Ansible или Astra Automation |
| Значок в области уведомлений, уведомления | StatusNotifierItem/XEmbed через `TrayIcon` в Avalonia, уведомления через `notify-send`/D-Bus. **Проверить на стенде** с панелью Fly |
| Обработчик `mailto:`, автозапуск | Файл `.desktop` с `MimeType=x-scheme-handler/mailto;`, `xdg-mime default`, `~/.config/autostart` |
| Один экземпляр (именованное событие Windows) | Именованный мьютекс .NET или локальный сокет в `$XDG_RUNTIME_DIR` для передачи `mailto:` первому экземпляру |
| Единый вход Windows (SSPI) | Kerberos через GSSAPI: в доменах ALD Pro, FreeIPA и Samba AD билет берётся при входе в систему, и `HttpClient` использует его сам. Для NTLM включить управляемую реализацию .NET (`System.Net.Security.UseManagedNtlm`, она уже используется в тестах) или поставить `gss-ntlmssp` |
| Установщик Inno Setup | Пакет `.deb` (самодостаточная сборка .NET в `/opt/mailclient`, ярлык, значки), опционально локальный APT-репозиторий организации |
| Пути `%APPDATA%` / `%LOCALAPPDATA%` | `$XDG_CONFIG_HOME` / `$XDG_DATA_HOME` (`~/.config/mailclient`, `~/.local/share/mailclient`) |

## Особенности Astra Linux

**Версии.** Astra Linux SE 1.8 основана на Debian 12 (glibc 2.36), SE 1.7 — на Debian 10 (glibc 2.28).
Для .NET 10 на x64 нужна glibc не ниже 2.27, поэтому самодостаточная сборка запускается на обеих версиях.
Отдельно ставить .NET не нужно, тем более что в репозиториях Astra есть только .NET 6–8.
Формально Microsoft перечисляет для .NET 10 только Debian 13, так что Debian 12 и 10 считаются
«работает, но не тестируется Microsoft». Риск невысокий, но его закрывает собственное тестирование на стенде.

**Замкнутая программная среда (ЗПС).** В режиме ЗПС ядро запускает только ELF-файлы (программы и
разделяемые библиотеки) с проверенной цифровой подписью. В самодостаточной сборке .NET это:
- исполняемый файл-загрузчик;
- `libcoreclr.so` и другие библиотеки среды выполнения;
- нативные библиотеки Avalonia (SkiaSharp, HarfBuzzSharp);
- SQLite (`libe_sqlite3.so`).

Их нужно подписать утилитой `bsign`, а в SE 1.8 — универсальным `bsign-integrator`, в составе которого
есть `bsign-dot-net` для .NET.

Ключ подписи бывает двух видов:
- **ключ организации.** Администратор добавляет открытый ключ в систему, и этого достаточно для внутренних машин;
- **подпись ГК «Астра» по партнёрской программе («Ready for Astra»).** Нужна для поставки в аттестованные системы.

Подпись встраивается в сборку `.deb` в CI. Какие ещё файлы проверяются в режиме ЗПС, нужно
**проверить на стенде** в режимах «Воронеж» и «Смоленск».

**Мандатное управление доступом (МРД, PARSEC).** Почтовый клиент работает с файлами только в домашнем
каталоге пользователя и с сетью. Особых действий обычно не требуется. Нужно **проверить на стенде** работу
на ненулевом уровне конфиденциальности: доступ к хранилищу ключей, сокету единственного экземпляра и
временным файлам вложений.

**Рабочий стол Fly работает на X11.** Avalonia поддерживает X11. Известна мелкая ошибка Avalonia на Astra
с обработкой вставки из буфера обмена (issue #16740), её надо учесть в редакторе. Сама Astra ведёт
документацию для разработчиков по Avalonia, то есть платформа на Astra используется.

**WebKitGTK.** Avalonia WebView на Linux использует WebKitGTK, а если есть WPE WebKit — предпочитает его.
Нужно **проверить на стенде**, какая версия `libwebkit2gtk` есть в репозиториях SE 1.7 и 1.8 и подходит ли
она Avalonia 12. Если на 1.7 версия окажется слишком старой, есть два пути:
- поддерживать только 1.8;
- для 1.7 показывать письма через встроенный HTML-рендерер без JavaScript. Для чтения почты он безопаснее,
  но редактор форматирования в этом случае будет проще.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Avalonia 12 + Avalonia WebView (рекомендуется)** | Открытая лицензия MIT. Один интерфейс для Windows и Linux. Переносятся модели представления и `editor.html` | Разметку и стили надо переписать, а затем заново проверить интерфейс |
| Avalonia XPF (запуск WPF-кода на Linux) | Минимум переписывания разметки | Коммерческая лицензия. WebView2 всё равно нужно заменять. Зависимость от поставщика |
| Отдельная Linux-программа на Qt/GTK | Нативный вид в Fly | Второй интерфейс на другом языке, двойная поддержка |
| Веб-клиент (ASP.NET + браузер) | Не нужна установка на рабочие места | Другой продукт: серверная часть, отдельная модель безопасности |
| Wine | Нет переписывания | WPF и WebView2 под Wine нестабильны. Непригодно для ЗПС и аттестованных систем |

## План работ (оценка)

1. **Стенд и прототип, 3–5 дней.** Виртуальные машины SE 1.7 и 1.8 в режимах «Орёл» и «Воронеж» (с ЗПС),
   пустое окно Avalonia 12 с WebView. Проверить WebKitGTK, хранилище ключей, трей, вход по Kerberos
   в домене ALD Pro/FreeIPA/Samba и запуск подписанной сборки в ЗПС.
2. **Отделение платформы, 1–1,5 недели.** Интерфейсы `ISecretStore`, `IPolicySource`, `IShell` (открыть
   файл или ссылку, mailto, автозапуск), `ITray`, `ISingleInstance` и диалоги. Модели представления больше
   не ссылаются на `System.Windows`. Текущая WPF-версия продолжает работать на этих интерфейсах.
3. **Интерфейс на Avalonia, 3–4 недели.** Главное окно, просмотр письма с карточками контактов, окно
   написания письма (`editor.html` без изменений), настройки, учётные записи, автоответы, правила, контакты.
4. **Linux-службы и поставка, 1–2 недели.** libsecret, `policy.json`, `.desktop` и mailto, пакет `.deb`,
   подпись `bsign`/`bsign-integrator` в CI, сборка на Linux в GitHub Actions.
5. **Испытания, 1–2 недели.** Тестирование на SE 1.7/1.8 и разных уровнях МРД, затем при необходимости
   подача в программу совместимости «Ready for Astra».

Итого 8–11 недель. После перехода на Avalonia Windows-версию тоже можно собирать из него и постепенно
отказаться от WPF.

## Риски

- Версия WebKitGTK на SE 1.7 (см. выше). Это главный технический риск, его снимает этап 1.
- Подпись для ЗПС через ГК «Астра» зависит от партнёрского соглашения и сроков проверки.
- Хранилище паролей в сессии Fly может отсутствовать. Запасной вариант — файл с правами 0600,
  который слабее DPAPI; это надо согласовать с ИБ заказчика.
- Внешний вид и поведение будут чуть отличаться от Windows-версии: шрифты, диалоги выбора файлов, печать.
